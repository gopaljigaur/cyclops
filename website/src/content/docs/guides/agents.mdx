## AgentConfig

`AgentConfig` is a Pydantic model that holds all runtime settings. Every field has a sensible default; you only need to set what you care about.

```python
from cyclops import AgentConfig

config = AgentConfig(
    model="groq/llama-3.1-8b-instant",
    temperature=0.3,
    max_tokens=1024,
    system_prompt="You are a concise technical assistant.",
    tool_mode="auto",
    max_steps=10,
)
```

| Field | Type | Default | Description |
|---|---|---|---|
| `model` | `str` | required | LiteLLM model string, e.g. `"gpt-4o-mini"`, `"groq/llama-3.1-8b-instant"`, `"ollama/qwen3:4b"`. |
| `temperature` | `float` | `0.1` | Sampling temperature. Lower is more deterministic. |
| `max_tokens` | `int` or `None` | `None` | Maximum tokens in the response. `None` uses the model default. |
| `system_prompt` | `str` or `None` | `None` | System instruction prepended to every conversation turn. |
| `tool_mode` | `str` | `"auto"` | `"auto"` detects native function-calling support; `"native"` forces it; `"naive"` uses prompt-based tool parsing (works with any model). |
| `router` | `Router` or `None` | `None` | Optional LiteLLM `Router` for fallback and load balancing. |
| `max_steps` | `int` | `10` | Most LLM completions in one run, guard rounds included; at least 1. |
| `max_total_tokens` | `int` or `None` | `None` | Most tokens one run may use, checked between steps. |
| `max_cost` | `float` or `None` | `None` | Most USD one run may cost, checked between steps. |
| `hooks` | `AgentHooks` or `None` | `None` | Lifecycle callbacks for observability and tool approval. See [Hooks](/guides/hooks/). |

## Constructing an Agent

Pass a config, an optional list of tools, and optional memory storage.

```python
from cyclops import Agent, AgentConfig, InMemoryStorage
from cyclops.toolkit import tool


@tool
def greet(name: str) -> str:
    """Greet someone by name."""
    return f"Hello, {name}!"


memory = InMemoryStorage()
config = AgentConfig(model="groq/llama-3.1-8b-instant")
agent = Agent(config, tools=[greet], memory=memory)
```

## run() and arun()

`run()` is the simplest entry point. It sends a message, handles any tool calls, and returns the final text response as a string.

```python
response = agent.run("Who invented the telephone?")
print(response)
```

`arun()` is the async equivalent. Use it inside coroutines or when running multiple agents concurrently.

```python
import asyncio


async def main():
    response = await agent.arun("Who invented the telephone?")
    print(response)


asyncio.run(main())
```

Both methods accept an optional `response_model` parameter for structured output. See [Structured Output](/guides/structured-output/) for details.

## Multi-turn conversations

The agent accumulates every user and assistant message in its internal history. Each call appends a user message and an assistant reply, so follow-up questions automatically have full context.

```python
agent.run("My name is Alice.")
agent.run("What is my name?")  # correctly answers "Alice"
```

Inspect the current history at any time with the `messages` property. It returns a shallow copy, so the internal state is not accidentally modified.

```python
agent.run("My name is Alice.")
agent.run("What is my name?")

for msg in agent.messages:
    print(msg["role"], ":", msg["content"][:60])
```

Each message in `messages` is a plain dict with at least `"role"` and `"content"` keys. Tool messages also include `"tool_call_id"` and `"name"`.

## reset()

Call `reset()` to clear the conversation history and start fresh without creating a new agent.

```python
agent.run("Remember: the code word is banana.")
agent.reset()

# History is now empty.
response = agent.run("What was the code word?")
```

## run_with_response() and arun_with_response()

When you need token counts or cost estimates alongside the text reply, use `run_with_response()`. It returns a `RunResult` instead of a plain string.

```python
result = agent.run_with_response("Summarize quantum computing in two sentences.")

print(result.content)
print(f"Tokens: {result.tokens_used}  Cost: ${result.cost:.6f}")
print(f"Tool calls made: {len(result.tool_calls)}")
```

See [Cost Tracking](/guides/cost-tracking/) for the full field reference.

## stream() and astream()

`stream()` yields text tokens as they arrive. For agents without tools this is true token-by-token streaming from the LLM. For agents with tools, the tool loop runs first, then the final answer streams.

```python
for token in agent.stream("Explain black holes briefly."):
    print(token, end="", flush=True)
print()
```

See [Streaming](/guides/streaming/) for detailed examples.

## start(): steer and cancel a run

`start()` begins a run in a task on the running event loop and returns a `RunHandle`. Await the handle for the `RunResult`, iterate it (once) for the run's [events](/guides/streaming/#run-events), and use it to steer or stop the run while it works.

```python
from cyclops.core.events import TextDelta, ToolCallStarted

handle = agent.start("Research the three largest moons of Jupiter.")

async for event in handle:
    if isinstance(event, ToolCallStarted) and event.name == "web_search":
        handle.steer("Only use sources from the last five years.")
    elif isinstance(event, TextDelta):
        print(event.text, end="", flush=True)

result = await handle
```

- `handle.steer(message)` adds a user message that the model sees in its next completion. A message that arrives during a completion goes into the one after, once the step's tool calls finish. If that completion was the final answer, the run takes another step to answer the message (guards then judge the new answer); when `max_steps` or a budget leaves no step for it, the run completes with the answer it has and the message stays at the end of the history for the next run. Steering a run that has finished raises `RuntimeError`.
- `handle.cancel()` stops the run. Tool calls in progress are cancelled and get a cancelled result, so the conversation stays valid, and awaiting the handle gives `stop_reason="cancelled"`. A completion in progress is dropped. Calling it again does nothing.

Cancelling the task that awaits a handle (or `arun()`) also cancels the run, but as a plain `asyncio.CancelledError`: the await raises it and there is no `"cancelled"` result.

`start(input, stream=False)` makes the completions without streaming, so each step's text arrives as one `TextDelta`. `arun()`, `arun_with_response()` and `astream()` are shortcuts over `start()`. Iterating a handle doesn't hold the run back the way `astream_events()` does: events wait in the handle until you read them.

## Step and budget limits

When tools are in use the agent can call tools several times before producing the final answer. Three limits bound one run, each checked between steps (a step is one LLM completion and the tool calls it asks for):

- `max_steps` caps the number of completions (default `10`).
- `max_total_tokens` caps the tokens summed over the run's completions.
- `max_cost` caps the run's estimated USD cost.

Reaching a limit is not an error. The run ends with `stop_reason="max_steps"` or `stop_reason="budget"` on the `RunResult` from `run_with_response()`, and `content` is empty. A step in progress always finishes, so a run can exceed a budget by its last step. A completion that reports no usage, or a cost LiteLLM can't price, doesn't count against a budget.

```python
config = AgentConfig(
    model="groq/llama-3.1-8b-instant",
    max_steps=5,
    max_total_tokens=20_000,
    max_cost=0.05,  # USD
)
```
